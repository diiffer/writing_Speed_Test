### 1. Введение

Целью данного проекта была разработка настольного приложения для тестирования и оценки скорости набора текста. Приложение должно предоставлять пользователю интуитивно понятный графический интерфейс, возможность выбора уровня сложности и отображение результатов в реальном времени.

### 2. Выбор технологического стека

Для реализации проекта был выбран следующий набор технологий:

- **Язык программирования C++17:** Выбран за высокую производительность, строгую типизацию и широкие возможности для работы с системными ресурсами, что является важным для отзывчивого настольного приложения.
- **Библиотека Dear ImGui:** В качестве GUI-фреймворка была выбрана ImGui из-за ее простоты, легковесности и модели "немедленного рендеринга" (Immediate Mode GUI). Это позволяет описывать интерфейс прямо в коде основного цикла, что значительно упрощает разработку и отладку по сравнению с традиционными фреймворками с объектной моделью.
- **Библиотека GLFW:** Используется для создания окна, управления контекстом OpenGL и обработки пользовательского ввода (клавиатура, мышь). GLFW является кросс-платформенной и минималистичной библиотекой, что идеально подходит для связки с ImGui.
- **API рендеринга OpenGL:** Выбран как проверенный временем и широко поддерживаемый стандарт для 2D и 3D графики, на основе которого работают рендер-бэкэнды для ImGui.

### 3. Проектирование и структура данных

Проект имеет модульную архитектуру, которая разделяет логику пользовательского интерфейса от основной логики самого теста.

- **`GuiManager`:** Центральный класс, отвечающий за все визуальное представление. Он управляет состояниями приложения (главное меню, процесс теста, экран результатов) и является "владельцем" объекта теста.
- **`TypingTest`:** Класс, инкапсулирующий логику теста. Он ничего не знает о графическом интерфейсе. Его задача — сгенерировать текст, принять от `GuiManager` текущую строку ввода и вернуть актуальное состояние в виде структуры `TestState`.
- **`WordGenerator`:** Вспомогательный класс, отвечающий исключительно за генерацию случайной последовательности слов на основе выбранного уровня сложности.
- **`TestState` (структура):** Ключевая структура данных для обмена информацией между `TypingTest` и `GuiManager`. Она содержит все необходимые поля: количество ошибок, флаг завершения, эталонный текст и вектор булевых значений для посимвольной проверки правильности.

Такое разделение позволяет легко изменять или тестировать логику теста независимо от его графического представления.

### 4. Описание функционала

Разработанное приложение обладает следующим набором функций:

- **Главное меню:**
    - Выбор уровня сложности: "Easy", "Medium", "Hard".
    - Выбор количества слов для теста.
    - Валидация ввода для предотвращения запуска с некорректными параметрами.
- **Процесс тестирования:**
    - Отображение эталонного текста и поля для ввода.
    - Динамический подсчет ошибок и отображение прогресс-бара.
    - Возможность досрочно прервать тест и вернуться в главное меню.
- **Экран результатов:**
    - Отображение итоговых метрик: WPM (слов в минуту) и общее количество ошибок.
    - Вывод оценки по 5-балльной шкале, рассчитанной на основе WPM.

### 5. Тестирование и отладка

Для проверки корректности работы приложения использовались следующие подходы:

- **Модульное тестирование:** Логика подсчета ошибок в классе `TypingTest` проверялась путем передачи заранее заданных строк (с ошибками и без) и сравнения результата с ожидаемым.
- **Интерактивная отладка:** Использовались возможности IDE для пошагового выполнения кода в методе `GuiManager::render()` для проверки корректности смены состояний (меню -> тест -> результаты) и правильности вычисления метрик.
- **Пользовательское тестирование:** Проводились многократные прогоны приложения с разными уровнями сложности и количеством слов для выявления аномалий в поведении интерфейса и логики.

### 6. Заключение

В ходе выполнения проекта было успешно разработано полнофункциональное приложение для тестирования скорости печати. Архитектурное решение с разделением логики и представления показало свою эффективность, позволив легко добавлять новый функционал (например, досрочное завершение и систему оценок), не затрагивая ядро тестовой логики.

**Возможные пути для дальнейшего развития проекта:**

- Добавление поддержки нескольких языков.
- Ведение статистики и построение графиков прогресса пользователя.
- Использование системы сборки CMake для упрощения компиляции на разных платформах.
